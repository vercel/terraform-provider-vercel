# vercel_project_passport (Resource)

Manages Passport as a standalone setting on an existing Vercel project. It does not create, import, or delete the project itself, and does not manage builds, Git settings, other protection methods, bypasses, or exceptions. Requires an eligible Enterprise team and Owner permissions.

Creating this resource enables Passport. Destroying it disables Passport, leaving the project, Connect application, and application connections intact. To stop managing Passport while keeping it enabled, use a Terraform removed block with lifecycle { destroy = false }.

If the project is also managed by vercel_project, set manage_passport = false on that resource and remove its inline passport attribute before using this resource. Do not give multiple resources ownership of Passport for the same project. Import adopts the existing Passport configuration without changing it; Passport must already be enabled.

## Example Usage

```terraform
# Standalone: the project already exists; only Passport is managed here.
resource "vercel_project_passport" "existing" {
  team_id         = "team_example"
  project_id      = "prj_existing"
  connector_id    = "scl_existing"
  deployment_type = "all"
}

# If you ALSO manage this project with vercel_project, set
# manage_passport = false there and omit its inline passport attribute.
# Removing the standalone resource disables Passport, never the project.
```

## Using it alongside vercel_project

The standalone resource can protect a project that Terraform does not otherwise manage. You only need its project ID and a pre-existing Connect application.

If Terraform also manages the project itself, explicitly give up inline Passport ownership first:

```terraform
resource "vercel_project" "app" {
  name            = "existing-app"
  manage_passport = false
  # Omit passport here. Keep your other existing project configuration.
}

resource "vercel_project_passport" "app" {
  project_id      = vercel_project.app.id
  connector_id    = "scl_existing"
  deployment_type = "all"
}
```

`manage_passport = false` makes project create/update follow-up requests omit Passport entirely. `ignore_changes` alone does not prevent the project resource from sending its observed settings. Do not configure inline Passport and this resource for the same project. The project resource still owns the project and can delete it.

For migration, set `manage_passport = false`, remove inline `passport`, and import the existing settings into this standalone resource. Review the plan before applying; import itself is read-only, but differences in your resource configuration can still plan an update.

## Removal and handoff

Deleting this standalone resource disables Passport. It never deletes the project or its Connect application. To leave Passport enabled and remove only Terraform ownership, replace the resource configuration with:

```terraform
removed {
  from = vercel_project_passport.app
  lifecycle {
    destroy = false
  }
}
```

The `removed` block requires Terraform 1.7 or later. Changing the project ID or an explicitly configured team ID replaces the attachment: Passport is disabled on the old project and enabled on the new one. Do not use `create_before_destroy` for replacements on the same project.

## Schema

### Required

- `connector_id` (String) The stable ID of an existing Vercel Connect OAuth application, available from the vercel_connect_application data source.
- `project_id` (String) The ID of the existing project. This resource never creates a project.

### Optional

- `deployment_type` (String) Deployments to protect: all, preview, prod_deployment_urls_and_all_previews, or all_except_custom_domains. Defaults to all.
- `team_id` (String) The team ID. Defaults to the provider team.

### Read-Only

- `id` (String) The project ID.

## Import

Passport must already be enabled. Import adopts only Passport settings, not the project or its lifecycle.

```shell
# Adopt Passport settings on an existing project without importing the project itself.
terraform import vercel_project_passport.existing team_example/prj_existing

# With a provider team configured, the project ID alone is sufficient.
terraform import vercel_project_passport.existing prj_existing
```
